# Idea4AI P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a working P0 vibe-coding idea validator: serial engine (`clarify` → `audience` → `novelty_guard` → `scorecard` → `verdict` → `report`) behind Next.js Web + API, with `MOCK_LLM=1` golden fixtures and §12 AC tests green.

**Architecture:** Single Next.js App Router app (`apps/web` layout flattened to repo root for P0: `src/`). Engine lives in `src/engine/` (extract to `packages/engine` in P1). Default store is in-memory for CI; Supabase schema SQL provided and used when env vars set. Pipeline is serial; multi-agent off.

**Tech Stack:** Next.js 15 (App Router), TypeScript, Zod, Vitest, Tailwind optional minimal CSS, Supabase JS client (optional at runtime), Node crypto for hashes.

**Spec:** `docs/superpowers/specs/2026-09-18-idea4ai-design.md` (v6+)

## Global Constraints

- Domain: vibe coding ideas only  
- Pipeline version string: `p0.1.0`  
- Score weights must sum to `1.0` (±1e-6); 8 dims only  
- Evidence id regex: `^ev_[a-z0-9]{8}_\d{3}$` with `run_short = alnum(run_id).slice(0,8).padStart(8,'0')`  
- L2/L3 without `url` → Zod parse fail  
- `evidence_ids` ⊆ `evidence[].id` refine **only** on `ValidationReport`  
- `caps_applied` enum: `novelty_veto` | `diff_or_dist_lt_30` | `pmf_weak_cap` | `build_gate_fail`  
- Cap order: novelty_veto → diff_or_dist_lt_30 → build_gate_fail → pmf_weak_cap  
- Reserved report keys always present; P0 values `null`: `monetization`, `pmf`, `experiments`, `canvas`, `pestle`, `pitch`  
- `MOCK_LLM=1` default for local/CI; no external LLM required to pass P0  
- No MCP/Skill in P0

```ts
export const EVIDENCE_ID_RE = /^ev_[a-z0-9]{8}_\d{3}$/;

export function runShort(runId: string): string {
  const alnum = runId.toLowerCase().replace(/[^a-z0-9]/g, "");
  return alnum.slice(0, 8).padStart(8, "0");
}

export type EvidenceGrade = "L0" | "L1" | "L2" | "L3";

export class EvidenceAccumulator {
  private seq = 0;
  readonly items: {
    id: string;
    claim: string;
    grade: EvidenceGrade;
    url?: string;
  }[] = [];
  constructor(private runId: string) {}
  add(input: { claim: string; grade: EvidenceGrade; url?: string }): string {
    this.seq += 1;
    const id = `ev_${runShort(this.runId)}_${String(this.seq).padStart(3, "0")}`;
    this.items.push({ id, ...input });
    return id;
  }
}
```

- [ ] **Step 2: selectFixture**

```ts
import { createHash } from "crypto";
export type FixtureName = "kill" | "test" | "build";
export function pickFixture(ideaText: string, override?: FixtureName): FixtureName {
  if (override) return override;
  const h = createHash("sha256").update(ideaText.trim().toLowerCase()).digest("hex");
  const n = parseInt(h.slice(0, 8), 16) % 3;
  return (["kill", "test", "build"] as const)[n];
}
export function mockRunId(fixture: FixtureName, ideaText: string): string {
  const h = createHash("sha256").update(ideaText.trim().toLowerCase()).digest("hex").slice(0, 12);
  return `mock_${fixture}_${h}`;
}
```

Note: golden **byte-stable** tests use **override** + fixtures with fixed run_ids inside JSON; pipeline when override set should return fixture content with `idea_id` patched, not re-hash run_id into fixture (or re-stamp evidence consistently). Prefer: when `MOCK_LLM=1` and override/header set, return fixture JSON with only `idea_id` replaced; keep fixture `run_id`/`evidence` as-is for stability.
